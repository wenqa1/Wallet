# 卡包（Wallet 平替）· 产品需求文档（PRD）

> 版本：v1.0　|　日期：2026-08-02　|　状态：评审稿

---

## 1. 背景与目标

### 1.1 背景

iOS 系统钱包（Apple Wallet）只允许添加少量支持 NFC/发行方合作的卡片，且部分功能需要较新系统版本。在低版本 iOS 上，大量银行卡、会员卡、交通卡**无法添加进系统钱包**，日常找卡、看卡号、看余额很不方便。

### 1.2 目标

做一款**钱包平替**应用，在本机把"卡"这件事管理起来：

- 像系统钱包一样展示和管理卡片；
- 卡面真实、好看，可自动匹配银行、也可完全自定义；
- 相机一照即可录入卡号，免去手抄；
- 记录余额、备注等扩展信息；
- **敏感数据本地加密、不上云**，做可信赖的私人工具。

### 1.3 非目标（明确不做）

- ❌ 不做任何支付 / 扣款 / 银联 / NFC 交易能力
- ❌ 不联网上传任何用户卡片数据
- ❌ 不做账号体系、云同步（v1）
- ❌ 不做银行官方联动（调余额接口等）

## 2. 目标用户

| 用户 | 描述 |
|---|---|
| 主要用户 | 低版本 iOS 用户，无法把卡加进系统钱包 |
| 次要用户 | 追求卡面美观、想集中管理多张卡的用户 |
| 潜在用户 | 需要记录会员卡、储值卡余额的用户 |

## 3. 功能需求

### 3.0 需求优先级定义

- **P0**：v1.0 必须交付
- **P1**：v1.1 迭代
- **P2**：后续

### 3.1 卡包管理（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F-01 | 卡片列表 | 钱包式轮播 / 网格视图，卡片按可自定义顺序排列 |
| F-02 | 添加卡片 | 相机扫描录入 或 手动填写，两种入口 |
| F-03 | 编辑卡片 | 修改任意字段 |
| F-04 | 删除卡片 | 二次确认后删除，敏感数据一并清除 |
| F-05 | 卡片详情 | 点击卡片翻转显示详细信息（卡号、有效期、CVV、余额、备注等） |
| F-06 | 搜索 / 排序 | 按银行名、卡片名、卡号后四位搜索；按类型 / 最近使用排序 |
| F-07 | 卡片类型 | 储蓄卡 / 信用卡 / 会员卡 / 交通卡 / 其他（影响默认卡面与字段） |

### 3.2 卡片字段（P0）

| 字段 | 敏感 | 存储 | 说明 |
|---|---|---|---|
| 卡号 | ✅ | Keychain | 录入时可手动输入或相机识别 |
| 持卡人 | ✅ | Keychain | 可选 |
| 有效期 MM/YY | ✅ | Keychain | 可选 |
| CVV | ✅ | Keychain | 仅信用卡，默认隐藏 |
| 银行/发卡行 | ❌ | SQLite | 决定默认卡面匹配 |
| 卡片类型 | ❌ | SQLite | 见 F-07 |
| 卡片昵称 | ❌ | SQLite | 如"工资卡" |
| 余额 | ❌ | SQLite | 自定义输入，可更新，可加备注 |
| 卡面 | ❌ | 见卡面系统 | 自动匹配或自定义 |
| 备注 | ❌ | SQLite | 自由文本 |

### 3.3 相机读取卡号（OCR）（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F-08 | 相机扫描 | 打开相机对准卡片，实时识别并框出卡号 |
| F-09 | 卡号识别 | 从识别文本中提取 13~19 位数字串，**Luhn 校验**通过则自动填入 |
| F-10 | 辅助字段识别 | 顺带识别姓名行、有效期（MM/YY 模式），填入表单供确认 |
| F-11 | 人工确认 | 识别结果可编辑、可重新扫描，确认后才写入 |
| F-12 | 权限处理 | 首次请求相机权限，拒绝时给出说明并引导手动输入 |

### 3.4 卡面系统（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F-13 | 内置卡面库 | 内置主流银行（工、农、中、建、交、招、邮储、平安、中信、浦发、民生、光大、广发等）**通用卡面**：银行主题配色 + 银行名文字，不复刻银行美术设计/Logo（规避版权，可上架），离线可用 |
| F-14 | 网络更新 | 启动时检查远端卡面清单版本，有更新则增量下载新卡面并缓存（失败静默回退到内置库） |
| F-15 | 自动匹配 | 录入银行卡时按银行代码自动匹配默认卡面，可手动更换 |
| F-16 | 自定义卡面 | 渐变配色 / 预设主题 / 相册选背景图（**可拍自己手里的实体卡**，个人管理自己的卡合规）/ 自定义文字与位置，实时预览 |
| F-17 | 卡面优先级 | 自定义卡面 > 远程卡面 > 内置卡面 > 兜底渐变 |

### 3.5 敏感信息遮挡（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F-18 | 默认遮挡 | 卡号列表/详情默认显示 `•••• •••• •••• 1234` |
| F-19 | 临时显示 | 长按卡片 / 点"显示"按钮临时明文，数秒后自动隐藏 |
| F-20 | 后台隐藏 | App 切到后台时清除界面上的敏感明文（防截图窥探） |

### 3.6 余额管理（P1）

| 编号 | 需求 | 说明 |
|---|---|---|
| F-21 | 余额录入/更新 | 数字键盘输入，支持小数，默认货币 ¥，可逐卡设置币种 |
| F-22 | 余额展示 | 卡片详情与卡面上显示余额；储值卡/会员卡更常用 |
| F-23 | 余额变更记录 | 可选：记录每次修改时间（不做流水账） |

### 3.7 设置（P1）

| 编号 | 需求 | 说明 |
|---|---|---|
| F-24 | 遮挡策略 | 遮挡开关、自动隐藏时长 |
| F-25 | 卡面更新 | 手动检查卡面更新；显示内置/远程卡面版本 |
| F-26 | 数据导出 | 加密导出（含 Keychain 数据） / 明文导出（仅非敏感字段） |
| F-27 | 关于 | 版本、隐私说明、免责声明 |

### 3.8 隐私与合规（P0）

| 编号 | 需求 |
|---|---|
| F-28 | 应用内隐私说明页：明确"所有卡片数据仅存本机，开发者无法读取" |
| F-29 | App Store 隐私标签（Privacy Nutrition Labels）：定位/追踪均为"未收集"；需声明"敏感数据本地存储" |
| F-30 | 卡面资源仅作个人本地展示，不包含可用于仿冒卡片的伪造元素（卡号、签名均为用户自己录入的真实数据，仅展示本人卡片） |
| F-31 | **不采用任何未经授权的聚合卡面图库**（如 Cardentify / Apple Pay 卡面提取站，其 GitHub 仓库已被 DMCA 下架）。内置库一律使用自制的通用化配色 + 行名文字设计 |

## 4. 非功能需求（NFR）

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动 < 1.5s；卡面图片懒加载；轮播 60fps 无掉帧 |
| 安全 | 敏感字段 Keychain 存储；SQLite 文件启用 iOS 文件保护（Data Protection）；无明文落盘 |
| 兼容 | 最低 iOS 16，适配 iPhone SE / 刘海屏 / 灵动岛；支持深色模式 |
| 可用性 | 全中文界面；单手可操作；关键操作有动效反馈 |
| 离线 | 核心功能（增删改查、自定义卡面）完全离线可用 |
| 体积 | 内置卡面压缩后 APK/iPA 增量 ≤ 15MB（不含自定义图片） |

## 5. 用户故事（核心用例）

1. 作为用户，我想打开 App 看到我的所有卡像系统钱包一样轮播展示。
2. 作为用户，我想用相机对准新办的银行卡扫一下，卡号就自动填好了。
3. 作为用户，我想给工资卡配上招行风格的卡面，不想用默认的。
4. 作为用户，我想看到卡里余额是多少，改完余额就能更新。
5. 作为用户，我不想让别人借我手机时看到完整卡号。
6. 作为用户，我想在银行更新卡面后，App 里也能自动看到新卡面。
